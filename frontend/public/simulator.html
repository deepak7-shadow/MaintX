Integration guide — wiring this into your main app

The simulator never assumes how your main app is built. It talks outward through two channels — pick whichever fits.

1. Embed as an iframe and listen for postMessage events. Every session start, approved change, unauthorized change, and session close is broadcast to the parent window:

<iframe src="maintx-simulator.html" id="sim"></iframe>

<script>
window.addEventListener('message', (e) => {
  if (e.data?.source !== 'maintx-simulator') return;
  const { type, payload } = e.data;
  // type: 'session_start' | 'change' | 'session_end' | 'log_integrity'
  if (type === 'change' && payload.status === 'unauthorized') {
    // forward to your backend, e.g.
    fetch('/api/maintenance/' + payload.job + '/alert', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(payload)
    });
  }
});
</script>

2. Same-document embedding. If you include this file's script directly in your app instead of an iframe, it also exposes window.MaintXSimulator:

window.MaintXSimulator.onEvent((type, payload) => { /* ... */ });
window.MaintXSimulator.getState();   // current controls, log, risk score
window.MaintXSimulator.loadPlan([{controlId, approvedValue, label}]);

3. Direct webhook. Enter a URL in the field below the log panel and unauthorized-change alerts will also be POSTed there as JSON, in addition to the postMessage broadcast. Note: when this page is running inside a hosted preview with a locked-down content-security-policy, cross-origin POSTs may be blocked — this works once the file is served from, or embedded in, your own app.

Each logbook entry is chained with SHA-256(previousHash + eventData), so editing an old entry breaks every hash after it — "Verify Chain Integrity" recomputes the chain and reports the first broken link, and "Simulate Tampering" mutates a past entry so you can demo the failure.
